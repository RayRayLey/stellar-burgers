# Stellar Burgers
Веб‑приложение космической бургерной, где любая форма жизни на краю Вселенной может собрать и заказать свой идеальный бургер.

[Макет](<https://www.figma.com/file/vIywAvqfkOIRWGOkfOnReY/React-Fullstack_-Проектные-задачи-(3-месяца)_external_link?type=design&node-id=0-1&mode=design>)

# Стек технологий
- Frontend: React, TypeScript
- Redux + Redux Toolkit + redux-thunk
- React Router
- CSS Modules + clsx
- Jest + Playwright

## Структура проекта
- src/components — переиспользуемые компоненты.
- src/pages — компоненты страниц под каждый маршрут.
- src/services — вся логика работы с Redux и API (слайсы, thunk‑функции, редьюсеры).
- src/utils — вспомогательные функции (например, fetchWithRefresh для работы с токенами).
- src/store — настройка Redux‑хранилища и подключение middleware.
- src/router — конфигурация маршрутов и защитных роутов (ProtectedRoute).
- src/styles — стили в виде CSS Modules, глобальные стили — в отдельном файле.

## Основные функции

- **Конструктор бургера**: подбор ингредиентов, динамический расчёт стоимости, ограничение на одну булку, счётчики количества ингредиентов. Оформление заказа — только для авторизованных пользователей.
- **Лента заказов (`/feed`)**: отображение списка, обновление в реальном времени, подсчёт стоимости, кнопка принудительного обновления, детальный просмотр по клику.
- **Личный кабинет и история заказов (`/profile`, `/profile/orders`)**: редактирование профиля с кнопками «Отмена»/«Сохранить», просмотр заказов со статусами, детальный экран заказа.
- **Авторизация и защита маршрутов**: страницы входа, регистрации, восстановления пароля; редиректы после успешных действий; защита приватных роутов через `ProtectedRoute`; сохранение запрошенного маршрута до авторизации.
- **Модальные окна через роутинг**: `/ingredients/:id`, `/feed/:number`, `/profile/orders/:number` — управление состоянием модалок через URL.

## Тестирование

### Интеграционные тесты (Playwright)
Протестированы ключевые пользовательские сценарии на странице конструктора бургера. Для изоляции от реального бэкенда настроен перехват запроса к эндпоинту `api/ingredients` с возвратом моковых данных (на базе HAR‑файла). Проверены:
* добавление ингредиентов (булок, начинок) в конструктор;
* работа модальных окон (открытие, закрытие по крестику и по оверлею);
* сценарий оформления заказа: сборка бургера, отправка запроса с моковыми токенами, проверка появления модального окна с номером заказа, очистка конструктора, закрытие окна.

### Модульные тесты (Jest)
Протестирована логика Redux‑слайсов `ingredients` и `burgerConstructor`. В тестах проверена корректная обработка всех типов экшенов:
* базовые экшены;
* асинхронные экшены (`.pending`, `.fulfilled`, `.rejected`);
* обработка неизвестного типа экшена (например, `{ type: "UNKNOWN" }`) при `undefined` в качестве начального состояния.
